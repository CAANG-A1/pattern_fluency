Volume 1 — Seeing Data

Eight patterns for working with data, building reports, and sharing them with a real audience.

Pattern #1

Group & Count

Use when: You need to know how many records are in each category.

Recipe: Category → X-axis. Record identifier → Y-axis. Power BI counts the records. You answer the question.

Example: Unit → X-axis. Name → Y-axis. Power BI counts people by unit.

Pattern #2

Change the Lens

Use when: The same data may need a different visual to answer a different question.

Recipe: Keep the data the same. Keep the fields the same. Change the chart type. Notice what becomes easier or harder to see.

Example: Bar chart answers "who has the most?" Pie chart answers "what percentage of the whole?" Same data, different lens.

Pattern #3

Read the Shape

Use when: You receive data and need to know what questions it can support.

Recipe: Label every column C (category) or N (number). List questions the data can answer. List questions it cannot. Know the shape before you build.

Example: No date column → cannot answer "how has this changed over time?" Find out if a date column exists before building a trend report.

Pattern #4

Filter = New Question

Use when: You want to focus the answer on one part of the data.

Recipe: Start with a broad chart using Pattern #1. Apply a filter. Restate the new, focused question out loud.

Example: "How many people are in each rank?" → filter to 129th Wing → "How many people in the 129th Wing are in each rank?"

Pattern #5

One Number Answer

Use when: One number answers the most important question in the room.

Recipe: Build a card visual. Choose the correct calculation (Count, Sum, Average). Read it as a sentence: "There are [number] [thing]." Label it so anyone understands it instantly.

Example: Card showing Count of Name = 12. Label: "Personnel with incomplete training."

Pattern #6

Design for the Reader

Use when: Your report needs to be understood by someone who did not build it.

Recipe: Name the specific reader. Rewrite all labels in plain English. Put the most important information top-left. Use color to guide attention to one thing. Add slicers where the reader needs control. Test with a real person.

Pattern #7

Publish, Test, Improve

Use when: Your report needs to leave your computer and be used by another person.

Recipe: Publish to Power BI Service (not the .pbix file). Open the link yourself and test it. Share with one person. Ask "what does this report tell you?" Improve based on their answer.

Pattern #8

Build the Full Loop

Use when: You are ready to turn a real question into a complete, published, presented report.

Recipe: Question → Read the Shape → Group & Count → Change the Lens → Filter = New Question → One Number Answer → Design for the Reader → Publish, Test, Improve → Present.

Volume 2 — Thinking in Data

Eight patterns for connecting data, calculating answers, and building dashboards that support real decisions.

Pattern #9

Connect the Tables

Use when: A question requires data from more than one spreadsheet.

Recipe: Find the question that needs two sources. Import both tables. Find the linking column — the column that appears in both. In Model view, drag the linking column from one table to the other. Build a chart using columns from both tables.

Example: Unit (Personnel) → X-axis. Name (Personnel) → Y-axis. Status = Incomplete (Training) → Filter. Result: incomplete training count by unit.

Pattern #10

Read the Trend

Use when: You need to know where something is going — not just where it is now.

Recipe: Find the date column. Place it on the X-axis. Place your measure on the Y-axis. Use a line chart — not a bar chart. Add a category to the Legend to compare multiple trends. Read direction, not just individual data points.

Example: Month → X-axis. Readiness → Y-axis. Unit → Legend. Story: Unit 144 is closing the gap with Unit 129.

Pattern #11

Derive the Answer

Use when: The number you need doesn't exist in the data yet.

Recipe: Write the calculation in plain English first. If you can't say it out loud, you're not ready to write it in DAX. Right-click the table → New measure. Translate plain English to DAX. Test. Use the measure in cards and charts — Power BI applies it automatically across every filter.

Example: "Percentage of people who completed training" → DIVIDE(COUNTROWS(FILTER(...Status="Complete"...)), COUNTROWS(Training)) * 100

Pattern #12

Drill to the Detail

Use when: A summary number raises a follow-up question.

Recipe: Write the summary question and the follow-up question. Create a hierarchy: right-click top-level field → Create hierarchy → add sub-levels. Drag the hierarchy to the X-axis. Enable drill mode using the arrow controls on the chart. Click a bar to drill down. Click the up arrow to return.

Example: Click Unit 129 → see breakdown by Rank. Click up arrow → return to all units.

Pattern #13

Design for the Decision

Use when: The goal is a specific decision, not just understanding.

Recipe: Name the decision in one sentence. Name the must-see number. Name the two or three supporting visuals. Remove everything else. Title the report as the decision — not the data. Test with the actual decision-maker.

Example: Decision: "Which unit gets priority scheduling?" Must-see: incomplete training count by unit. Context: trend over 6 months. Remove: everything else.

Pattern #14

Keep It Current

Use when: Your report needs to show current data without manual updates.

Recipe: Move your source data to SharePoint or OneDrive for Business. In Power BI Desktop: Data source settings → Change Source → point to the shared location. Publish to Power BI Service. Dataset settings → Scheduled refresh → On → set frequency. Enable refresh failure notifications.

Pattern #15

Close the Gap

Use when: A question can't be answered because the data doesn't support it yet.

Recipe: Write the question. Diagnose the gap: missing calculation → Pattern #11. Missing column → create a calculated column with DAX. Missing data source → Pattern #9. Close the gap. Answer the question that was impossible before.

Example: "Which people are overdue — not just incomplete?" → Missing column. IF(Status="Incomplete" AND DueDate<TODAY(), "Overdue", "Current"). Build the chart. Answer answered.

Pattern #16

Build the Full System

Use when: You are ready to move from a real unit need to a live, connected, decision-ready dashboard.

Recipe: Name the decision → Read the Shape → Connect the Tables → Close the Gaps → Write measures in plain English → Create measures in DAX → Build the visuals → Design for the Decision → Move data to SharePoint → Configure scheduled refresh → Publish, Test, Improve → Present.

Spot the Pattern — Volume 2 Scenarios

Choose the Pattern Before You Click

Scenario: Your commander asks, "Which unit has the most people with incomplete training?" You have a personnel file and a training file, both with a Name column.

Start with: Pattern #9 (Connect the Tables). Find the linking column. Build the relationship. Then Pattern #1 (Group & Count) with Pattern #4 (Filter = New Question).

Scenario: Your supervisor asks, "Are things getting better or worse?" You have monthly readiness data.

Start with: Pattern #10 (Read the Trend). Date on X-axis. Readiness on Y-axis. Line chart.

Scenario: Leadership needs to know the percentage of personnel who are training-complete — but that number isn't in any spreadsheet.

Start with: Pattern #11 (Derive the Answer). Write the plain English sentence. Translate to DAX. Test. Card visual with Pattern #5.

Scenario: The readiness number at the unit level looks fine, but someone suspects one specific rank is pulling it down.

Start with: Pattern #12 (Drill to the Detail). Build a Unit → Rank hierarchy. Enable drill mode. Click the unit to see the rank breakdown.

Scenario: You've built a report but nobody uses it because it's always a week out of date.

Start with: Pattern #14 (Keep It Current). Move the source to SharePoint. Configure scheduled refresh.
