Make Two Spreadsheets Talk

Before This Lesson
Data lives in separate places. I work with one spreadsheet at a time.
→
After This Lesson
Data is a connected system. Two tables together can answer questions that neither can answer alone.

Welcome to Volume 2

Volume 1 taught you eight patterns for working with a single spreadsheet. You can import data, build charts, add cards, apply filters, design for a reader, and publish.

Volume 2 starts with the most common problem real analysts hit: the answer requires more than one spreadsheet.

Your personnel data is in one file. Your training records are in another. Your budget is in a third. Each file answers part of the question. None of them answers it alone.

Today you're going to make two spreadsheets talk to each other — and answer a question that neither could answer on its own.

Pattern Review — Volume 1

Pattern #3 taught you to Read the Shape — to identify what a spreadsheet can and cannot answer before building anything.

Today you'll discover what happens when one spreadsheet's shape doesn't support your question but two together do. The answer was always there. It was just split across two files.

Before We Open Power BI

Think about a question you've wanted to answer that required information from more than one place.

Examples:

"Which unit has the most people with incomplete training?" — requires personnel data AND training records.

"Which department is over budget per person?" — requires budget data AND headcount data.

Write your question down. Then identify the two data sources it needs.

The Key Concept — The Linking Column

Two spreadsheets can only talk to each other if they share a common column.

Think of it like this: if Spreadsheet A has a column called Unit and Spreadsheet B also has a column called Unit, Power BI can connect them — one row in A links to matching rows in B.

Before you try to connect two tables, find the column they share. That column is the bridge.

Step 1 — Build Your Two Spreadsheets

For this lesson, create two simple Excel files.

File 1: Personnel.xlsx

NameUnitRank
Smith129TSgt
Jones144MSgt
Brown129SSgt
Garcia144TSgt

File 2: Training.xlsx

NameTrainingStatus
SmithSafetyComplete
JonesSafetyIncomplete
BrownSafetyComplete
GarciaSafetyComplete
MillerSafetyIncomplete

The linking column is Name. It appears in both files. Power BI will use it as the bridge.

Step 2 — Import Both Files

Loading Two Sources

Open Power BI Desktop.

Click Get Data → Excel Workbook.

Load Personnel.xlsx. Click Load.

Now click Get Data again.

Load Training.xlsx. Click Load.

You now have two tables in Power BI. Look at the right side — you should see both listed.

Step 3 — Create the Relationship

Making Them Talk

At the top of the screen, find the Model view icon on the left navigation bar. It looks like three connected shapes. Click it.

You should see two boxes — one for Personnel, one for Training.

Find the Name column in the Personnel table. Click and drag it to the Name column in the Training table.

A line appears connecting the two tables. That line is the relationship.

Click back to Report view.

If No Line Appeared

Check that both columns are named exactly the same — Name in both tables. Power BI is case-sensitive about column names in relationships. If one says "name" and the other says "Name," they won't connect automatically. Rename the column in one table to match.

What Just Happened

Power BI now knows that Smith in the Personnel table is the same person as Smith in the Training table. When you build a chart using columns from both tables, Power BI follows the relationship to combine the data correctly.

This is the moment your data stopped being two separate files and became one connected system.

Step 4 — Build the Cross-Table Chart

Answering the Question

Go to Report view. Click a blank area of the canvas. Select a bar chart.

In the X-axis box, place Unit from the Personnel table.

In the Y-axis box, place Name from the Personnel table (this counts people).

Now find Status from the Training table. Drag it to the Filters panel.

Check Incomplete.

Look at the chart. You are now seeing how many people per unit have incomplete training — a question that required two spreadsheets.

What You Just Learned

You may think you just learned how to create relationships.

You didn't.

You learned your ninth Pattern Fluency pattern.

When one spreadsheet can't answer the question, find the second spreadsheet it needs — and the column that connects them.

Pattern #9

Connect the Tables

Question: What question requires more than one spreadsheet to answer?

Recipe:

  • Write the question that needs two data sources.
  • Import both tables into Power BI.
  • Find the linking column — the column that appears in both tables.
  • In Model view, drag the linking column from one table to the other.
  • Build your chart using columns from both tables.
  • Answer the question that neither table could answer alone.

Example: Unit (Personnel) → X-axis. Name (Personnel) → Y-axis. Status = Incomplete (Training) → Filter. Result: incomplete training count by unit.

Drill #9

▶ The Connection Drill

Delete all visuals on the canvas.

Go to Model view. Remove the relationship line (right-click → Delete).

Rebuild the relationship: drag Name from Personnel to Name in Training.

Go back to Report view. Rebuild the cross-table chart using Pattern #9.

Delete and rebuild three times.

Each time, state out loud: "The linking column is ___ and it connects ___ to ___."

Common Mistakes

Mistake 1 — Column names don't match exactly

Power BI requires exact matches for relationship columns. "Unit Number" and "Unit_Number" are different. Check spelling, spacing, and capitalization before creating the relationship.

Mistake 2 — Building the chart before creating the relationship

If you drag a column from Table B into a chart before connecting it to Table A, Power BI may not know how to combine them correctly. Build the relationship first. Build the chart second.

Mistake 3 — Using a non-unique linking column

The best linking columns contain unique values — one row per person, one row per unit. If your linking column has duplicates in both tables, Power BI will create a many-to-many relationship that can produce incorrect counts. Use an ID column when possible.

Mistake 4 — Forgetting which table a column came from

When you have two tables, Power BI lists all columns from both. Hover over a field name to see which table it belongs to. Always know whether you're dragging from Personnel or Training — it matters.
