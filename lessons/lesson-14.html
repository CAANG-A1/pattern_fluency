Automate the Update

Before This Lesson
Reports require manual work to stay current. I update them when I remember.
→
After This Lesson
Reports can update automatically. When the data changes, everyone sees current information.

Welcome Back

Every report you've built in this curriculum has one problem: it's a snapshot. The data was current when you loaded it. An hour later — or a week later — the underlying spreadsheet may have changed, but the report still shows old numbers.

Today you'll fix that. You'll set up a report that updates automatically when the data changes.

Pattern Review

Pattern #7 (Publish, Test, Improve) taught you to share a report and get feedback. But a shared report is only valuable if it stays current. A report showing last month's readiness numbers when decisions need to be made today is worse than no report at all — it creates false confidence. Today's pattern makes your reports stay alive.

Before We Open Power BI

Think about the reports you've built. How often does the underlying data change?

Daily? Weekly? Monthly? When someone updates a spreadsheet?

The answer tells you how frequently your report needs to refresh — and what setup you need.

Two Types of Data Sources

File-based sources (Excel, CSV): the data lives in a file. When someone updates the file and saves it, Power BI can be set to reload it on a schedule.

Live sources (SharePoint lists, databases, web feeds): the data lives in a system. Power BI can connect directly and query it on demand.

Most military and government analysts start with file-based sources. That's what we'll configure today.

Step 1 — Move Your File to a Shared Location

Why Location Matters

For Power BI to automatically refresh data from an Excel file, the file must be in a location that Power BI Service can reach. A file on your personal hard drive only works when your computer is on and Power BI Desktop is open.

Move your Excel file to one of these locations:

  • SharePoint — the preferred choice for government environments.
  • OneDrive for Business — works with Power BI Service's scheduled refresh.

Copy your Personnel.xlsx and Training.xlsx files to a SharePoint document library your team can access.

Step 2 — Reconnect Power BI to the New Location

Changing the Data Source Path

In Power BI Desktop, go to Home → Transform data → Data source settings.

You'll see your current file paths. Click one and choose Change Source.

Navigate to the SharePoint location where you saved the file. Select it.

Repeat for any other data sources.

Click Apply changes. Power BI reloads from the new location.

Verify the data still looks correct.

Step 3 — Publish and Configure Scheduled Refresh

Setting Up Automatic Updates

Publish your report to Power BI Service (same as Lesson 7 / Pattern #7).

In Power BI Service, find your dataset (not the report — the dataset it's built on).

Click the three-dot menu next to the dataset → Settings.

Find Scheduled refresh. Toggle it On.

Set the frequency: Daily, Weekly, or a specific time.

Click Apply.

From now on, Power BI will automatically reload the data from SharePoint on your schedule.

If Scheduled Refresh Isn't Available

Scheduled refresh requires a Power BI Pro or Premium license. If you don't see the option, check with your IT administrator about your organization's license level. Some government organizations use Power BI Premium per capacity, which enables refresh for all users.

In the meantime, you can manually refresh the dataset in Power BI Service by clicking the refresh icon next to the dataset name.

What You Just Built

Your report now has two parts that work independently:

The report — the visuals, layouts, and design you built.

The dataset — the data behind the report, which now refreshes automatically.

When someone updates the Excel file on SharePoint and Power BI runs its scheduled refresh, everyone who has access to the report sees current data — without you doing anything.

What You Just Learned

You may think you just learned how to configure scheduled refresh. You didn't. You learned your fourteenth Pattern Fluency pattern. A report that requires manual updates is a report that will eventually be wrong. Move your data to a shared location. Connect Power BI to that location. Schedule the refresh. Then let it run.

Pattern #14

Keep It Current

Question: How do I make sure this report always shows current data without manual work?

Recipe:

  • Move your source data to SharePoint or OneDrive for Business — somewhere Power BI Service can reach.
  • In Power BI Desktop: Data source settings → Change Source → point to the shared location.
  • Publish to Power BI Service.
  • In Power BI Service: Dataset settings → Scheduled refresh → On → set frequency → Apply.
  • Test: update the source file, wait for the scheduled refresh, confirm the report updated.

A report that stays current without manual effort is a report that gets used. A report requiring manual updates is a report that gets ignored.

Drill #14

▶ The Live Data Test

After configuring scheduled refresh, test it manually:

Open your source Excel file on SharePoint. Change one number — add a row, change a status, update a value.

Go to Power BI Service. Find your dataset. Click the refresh icon (manual refresh).

Open your report. Did it reflect the change?

If yes — the connection is working. Scheduled refresh will do this automatically.

If no — check the data source path and credentials. The most common issue is a path that changed or credentials that need re-entering.

Challenge

Brief the person who maintains the source data: "When you update this file on SharePoint, the report updates automatically within [X hours]."

Teach Back

Explain why a file on a local hard drive can't support automatic refresh.

Explain the difference between the report and the dataset in Power BI Service.

Explain Pattern #14 in plain language:

Move the data to SharePoint. Point Power BI to that location. Schedule the refresh. The report stays current without manual work.

Common Mistakes

Mistake 1 — Leaving data on a local drive

A file at a local file on your desktop can only refresh when your computer is on and accessible to Power BI. Move it to SharePoint before configuring scheduled refresh.

Mistake 2 — Forgetting to test the refresh

Always test manually after setting up scheduled refresh. Change a value in the source file, manually trigger a refresh in Power BI Service, and confirm the report updated. Do not assume it works — verify.

Mistake 3 — Refreshing more often than the data changes

If your data updates monthly, a daily refresh wastes license refresh capacity and provides no benefit. Match the refresh frequency to how often the data actually changes.

Mistake 4 — No notification when refresh fails

In Power BI Service dataset settings, you can configure email notifications when a refresh fails. Turn this on. A silent refresh failure means your report is showing stale data and no one knows.

Homework

Move your most important report's data source to SharePoint.

Configure scheduled refresh.

Enable refresh failure notifications.

Share the report link (not the file) with the person who needs it most.

Tell them: "This report updates automatically. Bookmark the link."
